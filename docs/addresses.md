# Addresses

How a site declares its static addresses: explicitly, and nothing is left out without being said so.
A provider implements `StaticRouteProviderInterface::pages(): iterable<StaticPage>`; one that leaves
routes out also implements `Route\SkipReportingInterface::skipped(): array<string, string>`
(subject => why), which the exporter turns into `skipped-route` warnings. `Site::provide()` takes any
number of providers; the same path given twice is a `duplicate-page` warning (the first kept), and the
pages are rendered in the order of their paths.

Routes that must not be static (signed-in pages, posted forms, payments, per-visitor JSON) are not
enumerated, and `Site::dynamic()` names them so that links to them are not broken links
([The export](export.md#the-dynamic-host)).

## PageList

```php
new PageList(['/', '/about', '/blog/hello']);
new PageList(fn () => array_map(fn ($slug) => '/blog/'.$slug, $repository->slugs()));
new PageList([new StaticPage('/en/', locale: 'en', alternates: ['fr' => '/'])]);
```

The paths written out, or a closure that gives them; each a string (made a `StaticPage`) or a
`StaticPage`.

## RouteCollectionProvider

A router's routes: a symfony/routing `RouteCollection` (Symfony's router, the one omnibridge/laravel's
`Routing\ActionRoutes` reads from an application's `#[Route]` actions, symfony/routing's attribute
loader in plain PHP).

```php
new RouteCollectionProvider($routes,
    parameters: [
        'app_article' => fn () => $db->query('SELECT destination, slug FROM article WHERE published')->fetchAll(),
        'app_index' => fn () => [['destination' => 'japon'], ['destination' => 'usa']],
    ],
    include: null,                                   // fnmatch patterns of route names; null: all
    exclude: ['app_*_comments', 'newsletter_*'],     // fnmatch patterns
    actions: ['App\Action\\'],                       // the routes of these actions only (class prefixes)
    noSitemap: ['app_legal'],                        // their pages are not listed in sitemap.xml
);
```

| Argument | Type | Default | Effect |
|---|---|---|---|
| `routes` | `RouteCollection` | required | |
| `parameters` | route name => iterable of parameter sets, or a closure returning one | `[]` | the values of a route's variables, by its name or, for a localized route (`blog.fr`), by its canonical name (`_canonical_route`) |
| `include` | `?list<string>` | null | the routes read, by name |
| `exclude` | `list<string>` | `[]` | the routes left out, by name |
| `actions` | `list<string>` | `[]` | the routes whose `_controller` starts with one of these prefixes |
| `noSitemap` | `list<string>` | `[]` | routes whose pages `sitemap.xml` does not list |

- A route without a variable is one page; a route with variables one page per parameter set, the set
  cut to the path's variables.
- The path is generated by symfony/routing's `UrlGenerator` with strict requirements: a value the
  requirement refuses is skipped and reported; a parameter the path does not name is not added as a
  query string.
- Only GET routes are read (a route with no method restriction counts as GET); another is skipped and
  reported, as a route with variables and no source.
- The page carries its route, parameters, action (`Class` or `Class::method`, from `_controller`) and
  locale (`_locale`); a localized route's languages are each other's alternates (`hreflang` in
  `sitemap.xml`).

A run (a `RouteCollection` by hand, the host's handling by a closure; [The export](export.md#a-run)
has the whole script and output) reports:

```text
[warning] skipped-route article {"slug":"Not Valid"}: not generated: Parameter "slug" for route "article" must match "[a-z-]+" ("Not Valid" given) to generate a corresponding URL.
[warning] skipped-route comment: it answers POST, not GET
[warning] skipped-route feed: its path /feed/{page} has variables (page) and no source gives their values
```

## SitemapProvider

The addresses of the application's own sitemap (sitemaps.org's `urlset`, its `xhtml:link` alternates):
a site that already enumerates its addresses for the crawlers enumerates them for the export too.

```php
new SitemapProvider(renderer: $renderer);                  // rendered at build time, at /sitemap.xml
new SitemapProvider(renderer: $renderer, path: '/sitemap-index.xml');
new SitemapProvider(file: 'public/sitemap.xml');
```

| Argument | Default | Effect |
|---|---|---|
| `renderer` | null | renders `path` (as a resource, not listed in the export's sitemap) |
| `path` | `/sitemap.xml` | the sitemap's address |
| `file` | null | read from this file instead; one of `renderer` or `file` is required (`InvalidArgumentException`) |

A sitemap index (`sitemapindex`) is followed one level: each listed sitemap rendered by its path (a
`file` alone cannot follow it: `RuntimeException`). An address with a query string, or on another host
than the first one, is skipped and reported. A page's locale is the `hreflang` its own address has
among the alternates. A sitemap that does not render (a status other than 2xx) or is not XML is a
`RuntimeException`, which fails the build.

## Writing a provider

```php
use Omnibridge\Static\StaticPage;
use Omnibridge\Static\StaticRouteProviderInterface;

final class Documentation implements StaticRouteProviderInterface
{
    public function __construct(private readonly Catalogue $catalogue) {}

    public function pages(): iterable
    {
        foreach ($this->catalogue->packages() as $package) {
            yield new StaticPage('/docs/'.$package->key, route: 'docs', parameters: ['key' => $package->key]);
        }
    }
}
```

A path is absolute, with no query string and no fragment (`StaticPage` refuses them with an
`InvalidArgumentException`): a file is one address, whatever its query.
